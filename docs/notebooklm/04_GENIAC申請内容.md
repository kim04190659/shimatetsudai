## 1. GENIACとは（本件における理解）

GENIAC（生成AIアクセラレーションプログラム）は、国内の生成AI開発力を強化するための、国のコンテスト形式の支援プログラム。応募テーマの一つに「開発・実証において、国産の基盤モデルの活用を必須とする」という要件があり、ここでいう国産基盤モデルとは、日本国内で登記され、日本国内に開発拠点を持つ企業・大学等が開発したモデルを指す。

しまてつだいはこれまで、意思決定支援ダッシュボードの文章生成を海外の生成AI（Anthropic Claude）のみで動かしてきた。GENIACへの応募を視野に入れ、国産基盤モデルでも実際に動かせる状態を整備した。

## 2. きっかけと経緯

### 2.1 GENIAC適合性の相談

国のAI開発支援プログラムに詳しい**久地井先生**に、しまてつだいのサイト（https://shimatetsudai.vercel.app/ 、屋久島の分室ページを中心に）を共有し、以下を相談した。

- Claude/Notion（海外基盤モデル）を使っている場合、GENIACは対象外か
- 企業としてではなく、個人として動いている部分がある点の扱い

久地井先生からの回答:
> 国産基盤も検討してもらえれば大丈夫です。

すなわち、現状のClaude/Notion一本の構成のままだと応募要件を満たさないが、国産基盤モデルを併用すれば従来通り対象になり得る、という回答だった。

### 2.2 サイトの評価とCotomiの提案

サイトを見た久地井先生からは「本格的で驚いた」「数字も含めてリアルか」という質問があり、木村からは「オープンデータ（e-Stat、RESAS）を、生成AIへの命令で取得しているため正確だと思う」「意思決定支援という性格上、最終的には意思決定者の意見を取り込む必要があり、そこに工夫を入れていきたい」と回答した。

久地井先生からは、素晴らしい発想との評価とともに、具体的な国産モデルの候補として**Cotomi**（NECの国産LLM）が提案された。

> 国産モデルは「cotomi」は、いかがなのでしょうか。すでに条件クリアだと思います。

### 2.3 Cotomi利用方法の検討

木村がCotomiを使う方法を模索したところ、久地井先生から「検討すれば、バッチリ対象になると思います」との回答。

その後、さくらインターネットのAI Engine（複数の国産モデルをAPI経由で利用できる、月3,000回まで無料枠のあるプラットフォーム）経由でCotomi v3を試したが、2026-08-21時点では「This model is not available」というエラーが返り、個別契約が必要な可能性がある状態で、現時点では利用できていない。

### 2.4 実装アップデートの共有

意思決定支援ダッシュボードに国産LLM活用を実装したことを久地井先生に共有し、りとけい向けダッシュボードv7（国産LLM下書きタブ付き）のURLを提示。また、応募主体について「久地井先生として提出した方がいいか、NECで出すか、離島経済新聞で出すかも迷っている」と相談した。

さくらインターネットのAPIを経由させているため、Cotomi側と話をすればCotomiにも切り替えられる構成にしてある旨も併せて共有した。

久地井先生からの回答:
> 早速のアップデートをありがとうございます。ユニークなアプリケーションなので、ぜひご応募してもらえると助かります。

木村は「検討してみます」と一旦持ち帰っている。

## 3. 現在実装済みの内容（GENIAC実証として提示できるもの）

- **モデル切り替え可能な基盤**: 意思決定支援ダッシュボードの文章生成部分を、環境変数1つ（`SUMMARY_LLM_PROVIDER`）でモデルを切り替えられる設計にした。既定はAnthropic（最も安定）。選択したモデルの呼び出しが失敗した場合は、自動的に既定の安定モデルへフォールバックする仕組みを備え、国産モデルを積極的に試しながらもサイトの機能自体が止まるリスクを避けている。

  ```typescript
  // 環境変数1つで切り替える。既定は最も安定しているモデル
  const provider = process.env.SUMMARY_LLM_PROVIDER ?? "anthropic";
  ```

- **国産オープンモデルでの実証**: さくらインターネットのAI Engine経由で、研究機関が開発する完全にオープンな国産モデル「llm-jp-3.1-8x13b-instruct4」に実際にアクセスし、りとけい向け意思決定支援ダッシュボード（v7）で、住民・関係者の声からダッシュボード下書きを生成するところまで動作確認済み。
  - 出力は元データの数字・事実を一切崩さず、内容の捏造は確認されなかった。
  - 一方、指示した見出し構成には従わず、モデル自身の判断で見出しを作り直す、という指示追従性の面での違いは見られた。
- **Cotomi対応の準備**: さくらインターネットのAPIを経由する構成にしてあるため、Cotomi側との協議が整えば、同じ仕組みでCotomiにも切り替えられる。ただし2026-08時点ではAPI経由でのCotomi利用自体ができない状態。
- **実際の運用フロー確認**: 拠点スタッフが新しい議事録や住民の声をNotionに追加した後、パスワードを入力して更新ボタンを押すだけで、ダッシュボードの該当箇所（議論まとめ・生成AI下書き・現場の声）が国産LLMで最新化される、という一連の流れを実際に1つの論点（りとけい420島リソース配分）で動作させた。
- **なぜ国産LLMを使う意味があるか（応募理由の核）**: 住民や関係者が実際に語った意見、行政・団体内部で検討中の論点は、性質として機微な情報である。これをどの国のどの企業のサーバーで、どのように処理するかは、本来は島の側が選べるべきという立場を取る。国産モデルであれば、データ処理が国内で完結し、運用体制も日本語の一次情報で確認しやすい。単に応募要件を満たすためではなく、住民の声のような機微な情報の扱いを自分たちで選べるようにする、という意味の方が大きいと位置づけている。

## 4. 未解決の論点（応募に向けて詰める必要がある事項）

1. **応募主体を誰にするか** ― 木村自身が「久地井先生として提出」「NEC」「離島経済新聞社」のどれがよいか迷っていると発言しており、久地井先生からの明確な回答はまだない。
2. **Cotomiの利用可否** ― さくらインターネットのAI Engine経由では現時点で利用不可。個別契約が必要かどうかを確認中。
3. **個人 vs 企業（NEC）としての応募** ― 木村は「企業としてではなく個人として動いている部分もある」と発言済み。GENIACの応募資格上、この位置づけが応募主体の判断に影響する可能性がある。
4. **本番既定モデルを国産にするか** ― 現在の既定はAnthropic（Claude）のまま。国産LLMは「切り替えて試せる」段階で、本番既定にするかは未確定。
